A rate limit is not an empty account

A run died at "every funded provider returned a fatal error" with a working
account sitting unused. Google had answered 429 RESOURCE_EXHAUSTED — a
free-tier per-minute window, with the wait stated in the reply as 26 seconds —
and the message contains the word "quota", which is in the fatal list. So the
provider was marked dead, the chain demoted past it, and the run ended over a
wait measured in seconds.

Both kinds of error say "quota" and only one of them is permanent. A rate limit
is transient by construction: the window reopens. An empty account is not.
_is_rate_limit now separates them and is consulted before the fatal check, so
402 and 401 still demote and 429 no longer can.

The backoff also guessed where the provider had already answered. Against a
per-minute window a guess tends to guess short, and every early retry spends
another request from the same budget, which is how five requests a minute
became none. _server_retry_delay reads the retryDelay the provider sent and
takes it when it is longer than the guess.

Found while imscribing an instruction set: the pipeline could not reach any
model, and the harness was the suspect before the agent.

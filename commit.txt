Fix the bughunter specialist: crashing kwargs, and a dead workspace path

Two faults, one that crashed on launch and one that would have misdirected the
agent on every run.

The launcher passed max_tokens to a base constructor that names the parameter
max_think_tokens, so every invocation raised TypeError before doing anything.
Along the same path, --list-sessions and --continue unpacked list_sessions()
rows as (id, meta) pairs and indexed [0][0], but the method returns row dicts;
both are corrected to read row["id"]. output was accepted and silently dropped;
it now writes the trajectory after the run, as the other operators do, and quiet
maps to verbose rather than a nonexistent kwarg.

The deeper fault: the specialist's whole instrument battery lives in p4rapend/,
and the constitution, the registry, the manifest, the operator docstring, the
agent's own exit message, and the catalog entry all still pointed at
vuln_hunting/ — the directory's former name. An agent reading its constitution
was told to run its tools from a directory that does not exist. All twelve
references are updated; every path the constitution and registry name now
resolves, and bughunter_agent.py --selfcheck passes all three lanes (parity,
race, kernel ordinal gate).

bughunter is added to check_tools_deep.py, which now also asserts each operator's
list_sessions returns row dicts with an id — the exact shape the two unpack bugs
violated, so a regression fails a check instead of a run.

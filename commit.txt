The reasoning toggle reaches a served model too

IG_THINK was reaching only the local tensor lane, because that lane renders the
chat template itself. A model behind an OpenAI-compatible server never saw it:
the flag does not travel in the standard request body, so each deployment spells
it its own way and a request that omits it gets that server's default instead of
ours.

The three spellings, from Qwen's own agent configuration and OpenRouter's:

  vLLM / SGLang   extra_body={"chat_template_kwargs": {"enable_thinking": …}}
  DashScope       extra_body={"enable_thinking": …}
  OpenRouter      extra_body={"reasoning": {"enabled": …}}

The loop picks by the client's base_url and passes it on every completion. This
is what a vLLM-served Qwen3.5-27B on localhost:8000 needs, and it is the same
IG_THINK that governs the local lane.

Banking a result before reversing it becomes a strategy, not just a reading.

AREV empties the register and leaves open frames alone, so a result fused back
to depth zero is exposed to the next reversal while the same result held one
level up survives it. A program that establishes something, then reverses, then
bounds must open the region that will HOLD the result before the region that
COMPUTES it, and close them in that order. The Erdos-Turan proof does exactly
that: card_unorderedPairs is a `have` still in scope when the calc runs, so the
reversal inside the chain cannot reach it. The `have` is the outer frame.

Three places, so it is enforced where it is cheap and available where it is
wanted.

banked_count_check in lattice_flow reports every CLEAR that loses weight with
nothing banked behind it, with the remedy attached. Reachable as the
banked_count grammar tool, so the agents and MoDoT both have it; 50 grammar
tools now, registry 30 of 30, deep check green.

ob3ect carries it as Phase 9b of the report and on the artifact, so a generated
program says whether it lost a count to a clear. The design prompt gains the
strategy under EDGE ROUTING, with the wrong and right arrangements written out,
so programs are built that way rather than only checked afterwards.

The kernel gains `banked <word>`, which reads the flat arrangement as four
units cleared at the AREV and the nested one as clean.

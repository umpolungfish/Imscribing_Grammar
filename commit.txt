The required-argument registry documented a tool's arguments wrongly, and now
cannot.

compute_conflict_distance takes name_holistic and name_compositional. The
registry said name_a and name_b. That is worse than having no entry, because the
failure path hands the model the registry's names: every failed call sent it
back into the same wall with the same wrong names, and the correct call was
never among the patterns tried. A specialist reported the tool as broken. It was
not broken.

Corrected, and an audit added to the deep check: every documented argument name
must exist on the function it documents. All 27 entries pass. The check now
fails the run if they ever stop passing, so a rename that leaves the registry
behind is caught where it is cheap rather than by an agent looping against a
tool that works.

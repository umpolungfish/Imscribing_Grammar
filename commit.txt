zenodo_upload.py: Zenodo upload tool for IG publications (2026-05-28)
======================================================================

Interactive CLI uploader. Workflow: create deposition → upload files →
prompt for metadata → confirm → publish (or save as draft).

Features:
- Sandbox by default; --live for production (requires explicit confirmation)
- Token from ZENODO_SANDBOX_TOKEN / ZENODO_TOKEN env vars or interactive prompt
- Default creator: Mills, Lando (ORCID 0000-0003-0003-0552); override at prompt
- Default: open access, cc-zero license, publication/preprint type
- --draft: save without publishing
- --update ID: add files to an existing deposit
- --list: show all deposits with state and DOI

Usage: python3 zenodo_upload.py paper.pdf [more_files ...]

Previous: agents/true_agentic_agent.py: local inference bugs fixed (2026-05-27)
======================================================================

agents/true_agentic_agent.py

  Bug 1 — Wrong tool injection format in _LocalChatCompletions:
    Tool schemas were manually injected into the system message text using a
    <tool_schemas> tag. Qwen3's chat template uses <tools> and the model was
    trained on that format — <tool_schemas> is unrecognised. The justifying
    comment ("template may detect <tools> and skip re-injection") was wrong:
    the template branches on the `tools` parameter, not message content.
    _SYSTEM_PROMPT's IG TOOL REFERENCE section was wrapped in <tools>...</tools>
    which would collide with the template's own injection; renamed to
    <tool_reference>...</tool_reference>. Manual injection removed; tools now
    passed directly to apply_chat_template (main and CPU-fallback paths).

  Bug 2 — Greedy decoding + wrong max_new_tokens default in _LocalChatCompletions:
    Both mdl.generate() calls used temperature=None, do_sample=False (greedy
    decoding). Qwen3 model card explicitly warns against greedy decoding:
    causes performance degradation and endless repetitions. Fixed to
    temperature=0.7, top_p=0.8, top_k=20, min_p=0.0, do_sample=True
    (Qwen3 non-thinking recommended params). Default max_tokens also corrected
    from 4096 to 32768 (Qwen3 recommended default).

  Bug 3 — Tetractys sub-calls used HTTP client for local models:
    When running --model local or --model local:/path, _spawn_config["model"]
    is "local" or "local:...". The Tetractys protocol in _imscribe_system_emit
    resolved this through _build_client(), which either called sys.exit() if
    OPENROUTER_API_KEY was absent, or sent model="local" to OpenRouter
    (invalid). Tetractys never ran actual local tensor inference.
    Fix: detect local prefix and use _LocalOpenAIClient() directly.

  Bug 4 — No-op max_tokens cap in _LocalChatCompletions.create:
    `max_tokens = min(max_tokens, 4096)` with default max_tokens=4096 never
    reduced anything. Removed.

  Bug 5 — Dead first definition of _imscribe_system_emit / _imscribe_system_verify:
    Both functions were defined twice; the first definition (lines 882–902,
    no Tetractys, simple tuple assembly) was silently overwritten at module
    load time by the second definition (lines 1212+, full Tetractys protocol).
    The dead code was never called. Removed.

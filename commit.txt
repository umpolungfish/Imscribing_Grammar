zenodo_draft.py: fix image loading in build subdirs — 2026-06-27

Root cause of images not appearing in compiled PDFs when zenodo_draft.py builds
into a _*_build/ subdirectory: relative image paths like `images/foo.jpg` were
only resolved to absolute when the file existed; if the file was missing or had
a wrong name, the path fell back to the original relative form, which lualatex
couldn't find from the build subdir.

Fixes:
1. _build_preamble now accepts `source_dir: Path | None` and emits
   \graphicspath{{source_dir/}{source_dir/images/}} immediately after
   \usepackage{graphicx}. This tells lualatex to search the source directory
   for all relative image paths regardless of where it's invoked from.

2. compile_pdf now creates symlinks for any image directories (images/, img/,
   figs/, figures/) found alongside the .md source into the build dir before
   running lualatex. This is belt-and-suspenders on top of graphicspath.

Both fixes are applied automatically on every compile — no manual symlink needed.
Existing relative paths in markdown sources work without modification.

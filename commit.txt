The emergence frontier reads its own seeds

emergence_frontier reported on a list held in the process that computed it, so
the tool's contract could not be met: the frontier is a claim about an
accumulated landscape, and a stateless reader only ever sees one session's worth
of one. A caller that seeded pairs and asked for the frontier a turn later got
"no conflict distance computations in this session yet", and the eighteen-seed
file it was meant to summarise was never opened.

compute_conflict_distance now writes each pair to ig-docs/emergence_seeds.json
with the aspirational/reductive split the frontier actually reports on, replacing
any earlier round on the same holistic/compositional address so a recomputation
corrects the record instead of doubling it. emergence_frontier reads that store,
unions the session's own pairs onto it, and counts the two directions separately,
which is what makes the two-faced set — the primitives that claim in BOTH
directions — computable rather than assembled by hand afterwards.

The store is the constellation's ig-docs, not this repo's: the landscape spans
repositories, and pointing it at imscribing_grammar/ig-docs silently found
nothing.

Verification: run against the store with an EMPTY session it reproduces the
recorded eighteen-pair frontier exactly, both counts and the ten-element
two-faced set. The hand recomputation and the tool now agree, so the recorded
baseline is a check on the tool and not only on the script that stood in for it.

Seeds written before the store carried a veracity class keep their d_c, and the
class is a function of d_c, so it is derived rather than reported unknown.

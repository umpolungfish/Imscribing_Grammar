Point the QC tools at the mOMonadOS kernel, not the Python

Every m3iosis subcommand has a Rust counterpart in the kernel — fibonacci_qc,
braid_grammar, dyson, hqe, afdmc, hop, troq, triple_frame, manifold, gematria —
and the manifests named only the Python. The kernel section now comes first and
says plainly where the QC tools are meant to run; the m3iosis entry is retitled
as a duplicate of that surface and kept for what the kernel does not expose.

The kernel path is `cd ~/imsgct/mOMonadOS && ./run_serial_cmds.sh "<cmd>" …`,
which takes several commands per boot — worth stating, since one boot per command
is where the QEMU overhead would otherwise eat the advantage.

Also recorded there: `bg`'s winding is a closed form in the writhe rather than a
sum of eigenvalue phases, which is why it cannot pick up the error the Python
bridge carried until today.

Name every tool in the inline manifest, not just the first line's

render_inline said "Every tool is still named here, so nothing is invisible."
That was not true. It read the FIRST LINE of each curated entry and took up to
four backticked spans from it, so not one of MoDoT's ~90 ./ask flags, none of
the ~50 structural verbs, and none of the imasm sub-verbs appeared in any
manifest. A specialist could not know they existed without a file_read it had no
reason to make, which is why the flag menu kept being pasted in by hand.

The docstring is why nobody caught it: it asserted the property the code did not
have, so reading the code looked like confirming it.

entry_names now harvests the whole body — backticked spans (head, plus any token
carrying a name shape, plus short lowercase phrases like `la lookup`), long-form
flags, dot-separated verb runs, parenthetical enumerations such as the PARI/GP
and calc function lists, bare file names, hyphenated commands, and identifiers
carrying a digit, which is the shape that catches cl8nk, cl9nk, ob3ect and
imasm16_3 written bare in prose.

Names are cheap. Prose and argument shapes are what cost, and they still live one
file_read away in TOOLS_<domain>.md, so the reason the detail was pulled out of
the prompt in the first place still holds.

The domain-marker check was failing on math, chembio and editorial before any of
this and was being read as ambient drift. It was not drift. It was this defect,
reported accurately, every run. All five domains are green now.

m3iosis.paranumber is retired as a marker: it names a module that no longer
exists, which the generator itself reports as unresolvable. A marker asserting a
dead surface fails forever and teaches nothing.

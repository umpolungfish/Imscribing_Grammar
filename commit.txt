Thinking was hardcoded off at both template call sites

Every winding logged an empty THINK line and I read past it. The reason is that
enable_thinking was passed as a literal False at both apply_chat_template calls,
so the template emitted a closed <think></think> before the model wrote a token.
The loop has a THINK phase; the prompt was closing it in advance. A small model
choosing between twenty tools is exactly the case that needs the reasoning, and
this template's own instructions permit reasoning in natural language before the
call.

It reads IG_THINK now, on both call sites and in the provider, defaulting ON,
with the legacy MODOT_THINK still honoured. Verified against the template: on
emits an open <think>, off emits the closed pair.

The CPU fallback was also still rendering with the checkpoint's template rather
than the canonical one — the copy that gets forgotten, and a fallback speaking a
different protocol from the main path is a desync that only appears once the GPU
is gone. It renders through the same template and the same flag now.

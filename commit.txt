Local inference streams token by token, in process

What I wired first was not streaming inference — it was letting a subprocess's
stderr through, which shows the kernel's own progress print and hands the caller
nothing. The weights are already resident in this process, so the generation can
be watched directly.

LocalProvider._stream_generate uses transformers' TextIteratorStreamer: generate
runs on a worker thread, decoded text lands on a queue as it is produced, and the
drain loop calls on_token per piece while accumulating the whole answer as the
return value. An exception on the worker is re-raised after the drain rather than
disappearing with the thread. Sampling comes from the model's card, the same
table the silent path uses, so streaming and not streaming are one route.

Measured on Qwen3-1.7B: tokens arriving live, 40 characters returned, the text
identical to what the callback saw.

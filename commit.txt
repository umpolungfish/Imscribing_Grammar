Route the real catalog writers through one function

The slot-category guard added earlier, and the propagation moved into save()
before it, were both on a path the registration flow never takes.
ImscriptionCatalog.save() does not write IG_catalog.json. The canonical file is
a bare list of name, description and twelve glyphs, and cli.py json.dumps that
list directly at three sites — delete, guided-encoding update, and new-name
registration. None of them validated anything and none of them propagated;
cli.py contains no reference to sync_catalog or propagate_catalog at all. That
is why the catalog drifted across its consumers and why thirty slot-category
violations accumulated unseen: the checks existed, on a function nobody called.

write_canonical_catalog() validates the slots, writes the list, and propagates,
and the three sites call it. Propagation is a no-op for any path that is not the
canonical one, so temporary and test writes stay inert.

esoteric_librarian's four write sites are deliberately left alone: they write
esoteric_library/<name>.json, which are separate side catalogs, and sending them
through this helper would fire propagation to the canonical consumers.

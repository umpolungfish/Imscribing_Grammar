Uncap the guided imscribe pick so a reasoning model can answer

The per-primitive guided pick in generate_guided asked the LLM for ONLY an
option number plus one sentence, but capped the call at max_tokens=2000. A
reasoning model spends that budget thinking before it emits anything, so it
returned null content with finish_reason='length', and after 4 retries the
imscription failed outright. This intermittently broke `imscribe generate`
(and every jam TOOL: imscribe that leans on it), which is exactly where a
design call must never be capped so tight it cannot answer.

Raised the cap to 16000 so the reasoning completes and the number is
emitted. Verified: a name that previously failed on length (additive_energy)
now generates and registers in IG_catalog.json. Note it is slow (the pick
runs once per primitive and the model reasons fully each time); a follow-up
could disable reasoning for this trivial pick rather than widen the budget.

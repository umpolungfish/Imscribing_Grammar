A winding with no tool call is not a conclusion

"A winding that emits no tool call is a natural conclusion" was the comment, and
it ended the QC operator's run on a thought: the model wrote "I need to figure
out what tools I have… I can't actually access the file system", emitted nothing,
and the loop delivered that deliberation as the answer.

It is a natural conclusion only once the session has observed something. Before
that there is nothing to conclude FROM. The loop nudges once instead, naming the
two tools that act — run_command and file_read — and only concludes if the next
winding is empty too.

Worth recording why the model believed it had no filesystem: run_command and
file_read are in the schemas and in the roster injected every winding, but the
specialist REPLACES the base system prompt rather than extending it, so the
document that describes those tools is gone and the domain prompt is all that
remains. The nudge names them explicitly, which covers the symptom. Composing
specialist prompts onto the base instead of substituting for it is the actual
repair and is a design decision, not a patch.

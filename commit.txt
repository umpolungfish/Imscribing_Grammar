I stop imscribe generate spawning an agent to resolve name conflicts.
Conflicts aren't gated anymore at either the imscribe_system or
encode_system layer, so an agent session that used to reason through
differing primitives and re-call with convergence_justification had
nothing left to resolve -- it was loading a local model on every
conflicting name for a decision the tool already makes on its own.

_register_to_json_catalog's conflict branch now writes the proposed
tuple straight to IG_catalog.json, the same direct-write path the
new-name branch already used, matching imscribe_system's own commit
behavior for a re-imscription. Removed _agent_resolve_conflict and the
_PRIMITIVE_VALID_VALUES table + _valid_values_block helper it was the
only caller of -- dead code once nothing spawns an agent to hand that
table to.
